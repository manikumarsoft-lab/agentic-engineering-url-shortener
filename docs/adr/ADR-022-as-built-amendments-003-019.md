# ADR-022: As-Built Amendments to ADR-003 to ADR-019

## Status

**Proposed (awaiting human owner approval, CR-009)**

History: drafted 2026-10-16 with AI assistance (Claude Code) from the final assessment
([docs/reviews/final-assessment.md](../reviews/final-assessment.md) §3). It has no effect until
the human owner approves CR-009.

## Context

The lean slice (HD-CUT-002) was built without per-task ceremony, and several accepted ADRs
describe structures that were never built. This ADR records, per ADR, only the **amendments**:
places where the code is a legitimate lean-slice choice and the ADR should follow it.

Where an ADR restates a spec requirement, a plan §16 ruling or a Human Gate 4 ruling, the ADR is
**not** amended: rewording it would only move the conflict into `spec.md` or `plan.md`. Those
items are listed under "Not amended" with the task that changes the code. ADR-012 and ADR-014
have no amendments.

## Decision

Each amendment below replaces or qualifies the named part of the earlier ADR. Unlisted parts of
ADR-003..ADR-019 stand.

### ADR-003: Orchestration model

- **Amended**: Agents are plain functions `agent(ctx: dict) -> dict` registered in `AGENTS`
  (`src/orchestrator/agents/deterministic.py`), each executed in its own subprocess through
  `orchestrator.agents.runner`; there is no `Agent.execute(StageContext)` protocol. IDs are
  `<prefix>_<uuid4 hex>`; there is no injectable `IdGenerator`. The clock is injected into
  `Engine` (`Clock`, test `FakeClock` in `engine.py`), not taken from `src/common/`.
- **Not amended (code to change)**: disabled AI-backed stub (FR-ORC-027/030, T266); repeat-run
  determinism test (NFR-DET-001, T271).

### ADR-004: Application architecture and local execution

- **Amended**: Package layout is `src/shortener/` (`app`, `store`, `validation`, `codes`,
  `config`, `openapi`), `src/orchestrator/` (flat modules `engine`, `graph`, `store`, `audit`,
  `policy`, `security_scan`, `metrics`, `evidence`, `summary`, `workspace`, `changesets`,
  `keys`, plus `agents/`), `src/common/apikeys.py` and `src/cli/` (Typer). One network process:
  `orch serve` (shortener, `127.0.0.1:8000`). There is no orchestrator HTTP server (CLI only,
  A-011). Staging is a release copy under `var/staging/releases/<id>/` exercised by a
  subprocess smoke check, not a server on port 8100. Runtime paths as in ADR-021.
- **Not amended (code to change)**: `orch demo reset` (plan §16.3, T287); orchestrator HTTP API
  (plan §3, T284, or a CR removing it).

### ADR-005: Dependency graph representation

- **Amended**: Node kinds are `agent` and `gate` (gate kinds `approval` and `clarify`); joins
  are implicit (a node waits for all `depends_on`). There are no `sync` or `system` nodes, no
  `depends_on_any`, no `optional_inputs` and no dynamic `G-CLARIFY-{n}` / `G-EXCEPTION-{n}`
  patterns. Conditions are `{fact, equals | not_equals}` over run facts. `on_failure` ∈
  {`safe_stop`, `fail_run`, `rollback`, `compensate`}; `failure_edge` names the only successor
  allowed after compensation; `compensate` names a node's compensation agent. Runs pin the
  workflow `version`. Graph validation is in `graph.py` (no meta-schema file).
- **Not amended (code to change)**: CON II entry/exit criteria and owner per node (FR-ORC-005,
  FR-ORC-008, T252).

### ADR-006: Change sets and isolated workspaces

- **Amended**: Manifest fields are `scenario`, `variant`, `summary`, `provenance`, `base`
  (description and `files_sha256` of the baseline files patched), `tests_patch`, `impl_patch`,
  `new_tests`, `touched_files`, `contract_version_after`, `sha256`, `review`. The lock is
  `scenarios/changesets.lock.yaml`, written by `orch changeset lock` with a human approver key
  (key ID, role, timestamp, patch hashes); it is not anchored to a git tag. Each change set
  applies independently to one baseline (no R0→R1→R2 chain). The run workspace is copied from
  the working tree (`workspace.include` paths, normalized to LF), one per run
  (`var/work/<run_id>/`), not per attempt and not via `git archive`. A change set that alters
  `pyproject.toml` dependencies fails SEC-003 at `validate` instead of `manifest_invalid`.
- **Not amended (code to change)**: provenance label text (FR-ORC-034; accepted deviation
  proposed in CR-010; T258); `undeclared-scope` variant (SCN-B-AC5, T276); lock anchored to an
  annotated tag (plan §16.3, T279); R0 from `git archive` (T288).

### ADR-007: Contract-first API and schema versioning

- **Amended**: Code-first. The shortener OpenAPI document is generated by
  `python -m shortener.openapi`, committed at
  `specs/001-agentic-sdlc-url-shortener/contracts/shortener-api.openapi.yaml`, and compared by
  `tests/shortener/test_contract.py`; drift fails CI (CR-007). There are no Alembic operations;
  additive-only migration (CHG-003) is a review rule.
- **Not amended (code to change)**: CHG-003 as a policy check (FR-GOV-005, T253).

### ADR-008: Audit integrity

- **Amended**: There is no `audit-event.schema.json` validation and no `orch audit export`.
  `orch evidence export` writes `audit.json` and `chain.json` (validity, event count, head
  hash); `orch audit verify <run>` recomputes the chain.
- **Not amended (code to change)**: recording refused modification attempts as
  `AUDIT_TAMPER_REFUSED` (FR-OBS-004, T277).

### ADR-009: Policy model and exceptions

- **Amended**: Scanners are pip-audit (SEC-003; hash-pinned snapshot in runs, live in
  `orch release check` and CI) and a regex secret scan (SEC-004), not detect-secrets. SEC-002
  is "no open high-severity threat" from the threat review. Exceptions are requested with
  `orch exception request` (engineer or approver key) and approved with
  `orch exception approve` (approver key), followed by `orch run resume`; there is no
  G-EXCEPTION gate node.
- **Not amended (code to change)**: exception expiry, scope and review condition, rejection and
  non-waivable checks (FR-GOV-008/010, T254); licence and approved-dependency checks
  (FR-GOV-005, T253); separation of duties (FR-GOV-017, T262).

### ADR-010: Authentication and authorization

- **Amended**: There is no `x-required-roles` API. Required roles are declared per gate in the
  workflow YAML (`gate.roles`); an escalated gate requires `release-owner`. Exception requests
  need an engineer or approver key; approvals need an approver key. `orch changeset lock` needs
  a human approver key.
- **Not amended (code to change)**: agents limited to declared capabilities (FR-ORC-025, T275).

### ADR-011: Observability, metrics and MTTR

- **Amended**: Metrics are per run (`orch metrics <run>`) and carry
  `label: "demonstration data"` (not `measurement_class: demonstration`). MTTR is computed over
  recovered failure episodes, with unrecovered episodes counted separately. There is no
  per-mechanism breakdown and no `includes_human_wait` / `fault_injected` fields. Traces and
  spans are not implemented (BL-16).
- **Not amended (code to change)**: aggregate metrics across runs (FR-OBS-006, T270).

### ADR-013: Retry, fallback and safe-stop policy

- **Amended**: REL-005 (advisory fallback check) does not exist; fallback use is recorded as
  `FALLBACK_USED` and the node is marked `degraded`.
- **Not amended (code to change)**: approver-granted retry-budget extension instead of the
  implicit `RETRY_BUDGET_RESET`, and resolution evidence for non-timeout causes (plan §16.3,
  A-016, T274).

### ADR-015: Workflow state persistence

- **Amended**: IDs are `<prefix>_<uuid4 hex>` with prefixes `run_`, `dec_`, `exc_`, `ep_`; not
  ULIDs. Artifact content is stored inline as JSON in the `artifacts` table, not under `var/`.
- **Not amended (code to change)**: the state-rebuild-from-audit consistency test (T241 scope).

### ADR-016: Human approval model

- **Amended**: There is no `decision_source` field. Scripted decisions appear only in tests;
  evidence export refuses runs labelled `test`.
- **Proposed accepted deviation (CR-009, G4)**: the release gate `approve-release` offers
  approve / reject_rework / reject_terminate / escalate (reject_terminate → `ABORTED`) instead
  of ruling 4's ready / not_ready / escalate (not_ready → `FAILED`). The ruling is **not**
  amended; the deviation is kept for this submission because changing the code now would make
  the recorded evidence inconsistent with it. Aligning the code is future work (G4).

### ADR-017: Dynamic replanning

- **Amended**: Replanning events are `ARTIFACT_VERSION_CREATED`, `REPLAN_STARTED`,
  `NODE_STALE`, `GATE_REVOKED` and `REPLAN_COMPLETED` (not `ARTIFACT_STALE`); there is no
  `GRAPH_VERSION_CREATED` and no input-hash memoization. Replanning is triggered by
  `Engine.new_artifact_version` and by `reject_rework`.
- **Not amended (code to change)**: late-ambiguity suspension (SCN-A-AC4, FR-ORC-022, T264).

### ADR-018: Testing strategy

- **Amended**: Test-first is recorded per scenario run: the `test-red` artifact (new tests fail
  before the implementation patch) and the `test-results` artifact (full shortener suite
  passes after it). There is no `tools/check.py`, coverage report, `req` marker plugin or
  per-task TDD evidence log. Fault injection is enabled through labelled entries in
  `scenarios/registry.yaml` (run label `fault-injection`); there is no `FAULT_INJECTED` event.
- **Not amended (code to change)**: refusing unlabelled fault injection via `--fact` (G2);
  coverage gate (PVT-007, T281); the Constitution IV record for the baseline is a human
  decision (T256).

### ADR-019: Analytics consistency

- **Amended**: Analytics and the `analytics_write_failures` counter are baseline shortener
  features (HD-SCN-001), not delivered by the SCN-A change set. The counter is reported by
  `GET /health/ready`.
- **Not amended (code to change)**: a test of exact counts under concurrent redirects (A-013,
  G6).

## Consequences

- ADR-003..ADR-019 describe the code once CR-009 is approved, except for the "Not amended"
  items, which stay open with task IDs in `tasks.md` Phase 13 and in README "Known gaps".
- No accepted ruling (Human Gate 4 rulings 1–4, plan §16) is changed by this ADR.
